3. Developer Responses to Client Brief (Section 16 Confirmation)
OmmNoMi provides definitive technical specifications for the 5 key architectural decisions requested in Section 16 of the client brief:
Topic OmmNoMi Proposed Technical Architecture Operational Impact & Benefit
1. Table Architecture Implement a Two-Tier Header-Detail Pattern:
• TimesheetSubmission (Parent: Week Ending, Employee, Total Days, Status).
• TimesheetEntry (Child: Activity, Actual Days, Notes).
• TimesheetOutput (Finance Archive: Denormalized flat snapshot rows).
• TimesheetActivity (Controlled Catalog Master). 		Guarantees relational data integrity, enables real-time sum validations, prevents orphan records, and isolates financial archives from UI operations.
2. Employee Master Extend Orbit's existing Employee table with 3 physical columns:
• IsBillable (Yes/No)
• DayRateAED (Price / Decimal, e.g. 2500, 3500, 4000)
• Team (Enum: Business Development, Recruitment, SET, Finance, Performance) 		Zero disruption to live profiles. Controlled fields editable exclusively by HR/Finance Admins. Rates are auto-fetched and never manually typed.
3. Revisions & Voids Audit-Safe Voiding Workflow:
• Submissions are strictly locked upon submission.
• Authorized reopen marks original TimesheetOutput rows as Invoice Status = "Superseded".
• Resubmission (e.g. v2) captures corrected days and appends fresh finance rows. 		Zero Duplicate Billing risk in Finance. Forensic historical audit trail remains 100% intact without silent overwrites or data loss.
4. Submission Lock • Editable_If rule: AND([Status] = "Draft", [EmployeeID].[Email] = USEREMAIL()).
• Slices hide Edit/Delete actions once [Status] = "Submitted".
• TimesheetOutput table set to Read-Only / System-Append Only. 		End-users cannot tamper with historical timesheets once submitted. Creates a legally robust, audit-proof billing pipeline.
5. Future GSC Split The Entity field in TimesheetActivity is designed as an extensible controlled tag (UAE, Qatar, KSA, HoldCo, GSC). Fully forward-compatible with BLR's upcoming entity reorganization without requiring structural database schema redesigns later.
4. AppSheet Configuration Protocol (Rule A2 Strict SOP Adherence)
In strict accordance with OmmNoMi Rule A2, database and application configurations are delineated across four distinct levels:
Level 1: Google Sheets Level (Physical Columns)
Employee: Add IsBillable, DayRateAED, Team.
TimesheetActivity: ID, Name, Description, CostCentre, BillableStatus, Entity, ProjectOwner, Status, System Audit.
TimesheetSubmission: ID, EmployeeID, WeekEndingFriday, SubmissionDate, Status, TotalDaysWorked, Notes, System Audit.
TimesheetEntry: ID, SubmissionID, ActivityID, ActualDaysWorked, LineNotes, System Audit.
TimesheetOutput: Exact 14 columns matching client Excel template.
Level 2: AppSheet Table Level (Structure & Modes)
Schema Regeneration: Regenerate existing Employee table.
New AppSheet Tables: Add TimesheetActivity, TimesheetSubmission, TimesheetEntry, TimesheetOutput.
Update Permissions:
• TimesheetSubmission: Adds, Updates.
• TimesheetEntry: Adds, Updates, Deletes (Parent IsPartOf = TRUE).
• TimesheetOutput: Read_Only (System action append).
• TimesheetActivity: Updates_Only (Admin full CRUD).
Level 3: Column Type Level (Types, Refs & Rules)
Enum Refs: TimesheetSubmission.EmployeeID (Enum Ref → Employee), TimesheetEntry.ActivityID (Enum Ref → TimesheetActivity).
Friday Validation: WEEKDAY([WeekEndingFriday]) = 6.
Numeric Constraints: AND([ActualDaysWorked] > 0, [ActualDaysWorked] <= 7).
Initial Value Formulas:
• WeekEndingFriday: TODAY() + (6 - WEEKDAY(TODAY()))
• EmployeeID: ANY(SELECT(Employee[ID], [Email] = USEREMAIL()))
• InvoiceStatus: "Not Invoiced"
Level 4: Virtual Column Level (Strict In-Memory)
TimesheetSubmission.CalculatedWeeklyTotal:
SUM([Related TimesheetEntrys][ActualDaysWorked])
TimesheetSubmission.DuplicateCheck:
COUNT([Related TimesheetEntrys][ID]) <> COUNT(UNIQUE([Related TimesheetEntrys][ActivityID]))
TimesheetEntry.ActivityDescription:
[ActivityID].[Description] (Hover / detail query)
Employee.IsTimesheetSubmittedThisWeek:
Dynamically computes current weekly compliance state.
